# turbo_api_generated (EXPERIMENTAL)
Contract between the Turbo apps, the admin dashboard and the API. **This file is the source of truth. Change it first, then code.**

## Conventions
- **Money** is an integer number of pesewas (`3500` = GH₵35.00). Never floats, never strings.
- **Ids** are UUIDs. **Times** are ISO 8601 in UTC. JSON keys are camelCase.
- **Pagination** is cursor based: `?cursor=&limit=`; responses carry `page.nextCursor` and `page.hasMore`. No offset pagination.
- **Errors** are RFC 9457 `application/problem+json` with a stable `code`. Clients switch on `code`.
- **Idempotency**: every endpoint that moves money or sends SMS takes an `Idempotency-Key` header. Same key and same body returns the original result; same key and different body is 409 `idempotency_key_reused`.
- **Deletes** are soft deletes. Nothing financial is ever hard deleted.
- **Auth**: `Authorization: Bearer <JWT>` (15 min). Web clients hold the refresh token in an httpOnly cookie; mobile clients hold it in secure storage and send it in the body. Rate limits return 429 with `Retry-After`.
- **Responses any operation can give**: 426 `upgrade_required` (app too old; not on `/app-config` or `/health`), 429 (rate limited) and 503 (busy, with `Retry-After`). Operations list the other statuses they can return.
- **Releases**: operations tagged `x-release: v1.1` are specified but must not be built for v1.
- **Roles**: `x-roles` on each operation. `admin:<role>` means that staff role or `super_admin`.
