# API endpoint tracker

Every endpoint in `api/openapi.yaml`, which screen uses it, and whether it is wired in and verified. Built from the contract, `docs/api-integration.md` (the backend's guide for 0.2.2) and the page → API map in `prompts/01` to `05`, cross-checked against the dashboard code.

## How to keep this up to date

- **Integrated = Y** only when committed app code calls the endpoint through the generated client (`apps/admin_dashboard` via `openapi-fetch`, the Flutter apps via `packages/turbo_api`). Write which app, e.g. `Y (dashboard)`.
- **Tested = Y** only when a person or test has seen the call work **against the real API** (local `:3000` or staging), including its main error case. The in-browser demo server, Prism and unit tests do not count, because none of them is the backend. Write how and when, e.g. `Y (staging, 2026-11-03)`, and add a line to the verification log below.
- Never mark Y on a guess. If something is half done, leave N and say why in the verification log.
- When the contract changes, run `npm run api-tracker` from the repo root. It rebuilds the table from the contract, the prompts and the dashboard code, and keeps every Integrated and Tested cell already marked. Edit only those two cells by hand; anything else you want to say goes in the sections below the table (the Notes column is regenerated).
